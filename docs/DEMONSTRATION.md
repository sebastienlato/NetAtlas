# Thesis demonstration and speaking guide

Target audience: thesis examiners. Allow **12 minutes** plus questions. Use the
isolated install in INSTALLATION and the private candidate deck. The claims below
are about authored fixtures and bounded local behavior. No screen action runs the
whole pipeline. Read controls never initiate collection, scheduling or derivation.

## Four distinct entry points

1. **Authored collection:** the evaluation command in INSTALLATION starts four
   temporary literal-loopback greeting services, captures/spools, ingests, derives
   and searches through ordinary modules. Its exact source/manifest hashes stay in
   a new private report. This shows NetAtlas collecting its own evidence.
2. **Presentation seed:** `make thesis-demo` explicitly appends authored evidence to
   the selected DB, derives the fixed core pack and enriches. It contacts no targets.
   Its documentation addresses are never translated into executable loopback plans.
3. **Read UI:** search, places, map, timeline, inspection and operations read retained
   sources. They do not scan, derive, reconcile worker authority or auto-refresh data.
4. **Worker/schedule qualification:** the full check runs two actual worker processes
   on separately authored HTTP/TLS loopback fixtures through scheduled admission.
   Review that acceptance evidence separately from the standalone throughput trial.

## Source identity and negative cases

Use IDs/digests shown on the current result card, then its own inspection button.
Never copy a prior rehearsal UUID into a new run, combine a source with another
source's derivation, or interpret a shared evidence blob as shared history. The seed
prints its clock, canonical dataset hash and exact validity window (minus one day,
plus seven days). Source UUIDs and resulting digests change each run. Reproducibility
means the same authored scenario/count semantics, not identical current timestamps.

Wrong/missing/expired/suppressed source bindings return generic 404. Automated API
acceptance exercises these cases plus expired/future datasets with no usable geography.
The browser regression separately checks inert hostile HTML, withheld markers,
unverified expired certificates, no external resource loads, mobile layout and Axe.
These checks do not establish a comprehensive sanitizer, real-input permission or
complete assistive-technology certification. Never add hostile or sensitive owner
content just to demonstrate a failure.

## Worker/schedule demonstration evidence

Full `make check-db` includes the scheduled two-process HTTP/TLS lost-ACK drill:
two original sources, three shared connection permits, two dropped acknowledgements,
no extra measurement/outbox duplicates. Other cases cover kill/restart uncertainty,
boot fencing, heartbeat loss, backpressure, suppression and globally stopped restore.
These are executable acceptance tests, not a persistent owner coordinator. No worker
DB secret is provisioned. No benchmark converts the drill into a distributed rate.

The authored scheduling evaluation preserves 12 routed / 2 unrouted / 4 unknown IPv4
addresses, separate IPv6 regions/seeds, and a seedless region. At seeds 7/8/9 its
14 eligible endpoints partition into 6 sampled-out + 1 deferred + 7 scheduled.
Scheduled, admitted, measured, incomplete, retained and refreshed remain distinct.
Offline logical shards partition one plan, never multiply budgets or imply global workers.

## Evidence, limitations and costs for questions

[EVALUATION_REPORT](EVALUATION_REPORT.md) contains the complete per-class failure
ledger, denominators, provenance and original run; preserve it as the Phase 13 record.
The 30-case corpus is same-author, purposive and separately labelled, not blinded,
second-rater or randomly sampled. Product-assertion precision is 6/6 nginx, 3/3 OpenSSH,
1/1 Postfix and undefined Apache; recall 6/7, 3/4, 1/1 and 0/1. Role scoring is separate
and lower. 21/30 yield no candidates, one preserves multiple products/roles. Eight
unsupported classes remain misses. Nominal intervals only expose small denominators.

The original three local repetitions used 128 endpoints / 384 sources, 10 complete
queries per shape after warm-up: current-evidence p50 7.878–8.317 ms, history p50
14.163–14.305 ms. The durable three-commit pipeline achieved 108.6–112.5 sources/s;
the separate four-service standalone pipeline achieved 1.298–1.306 sources/s under
ordinary pacing. No global, concurrent, cold-cache or sustained throughput claim.
Relations including indexes grew 565,248 to 4,276,224 B; two repeated blobs totalled
only 94 B, an intentionally unrealistic deduplication-heavy population.

No paid service is required for this demonstration. Existing hardware, local disk,
electricity and preparation/operator time still have costs; none were priced or
measured. Worldwide cost would depend on authorized endpoint/port population,
revisit intervals, response sizes, WAL/indexes/backups, bandwidth, staffing and
network policy. Local fixture slopes cannot price worldwide operation. Shared-lock
serialization, protocol/IPv6/vantage/retention bias, unverified assertions, approximate
geography and unknown radii constrain conclusions. OpenSearch remains deferred.
